  - Protocols Identified: TCP and telnet
  - Attack Footprint: Lack of encryption (Telnet) allows full credential harvesting and session hijacking via sniffing.

- WHAT I LEARNED:
  I learned that legacy text-based protocols like Telnet stream keyboard data character-by-character 
  in absolute cleartext over the wire, sending single-byte packets for every individual keystroke. 
  The complete lack of cryptographic protection means that standard line terminators (\r\n) and 
  sensitive operational credentials can be effortlessly intercepted and read by anyone with a basic 
  packet sniffer on the path.

- WHAT IT MEANS IN REAL LIFE:
  When an organisation continues to use unencrypted management protocols, they leave their entire 
  infrastructure exposed to total compromise via passive sniffing. An attacker sitting on the network 
  can map out system versions, steal administrative passwords without running aggressive scans, and hijack 
  active sessions. Security posture dictates that Telnet (Port 23) must be entirely deprecated and 
  replaced with SSH (Port 22) to enforce data-in-transit encryption.

  In a corporate environment, unmonitored authentication endpoints are constantly targeted by background 
  internet noise and targeted dictionary attacks. Defenders must implement automated log-parsing daemons 
  like Fail2Ban to dynamically block offending IP addresses after a specified threshold of failures.

🔒 SECTION 3: NMAP DEEPER SCAN FINDINGS
------------------------------------------------------------------------

- WHAT I DID:
  Executed advanced network enumeration scans against the local loopback adapter (localhost) 
  using Nmap via the Zenmap GUI. Focused on service version detection using 'nmap -sV -O localhost', 
  port restrictions via 'nmap -p 1-1000 localhost', and comprehensive aggressive script evaluation 
  using 'nmap -A localhost'.

- WHAT I FOUND:
  Analyzed the differences between a basic ping sweep and interactive service scans:
  - Service Banner Identification (nmap -sV -O localhost): The basic scan only shows if a port is 'open'. The -sV flag forced a protocol handshake, exposing the exact application name, service type, and firmware version running behind the port. The -O flag leveraged TCP/IP stack fingerprinting (analyzing TTL and window sizes) to map and guess the underlying kernel version.
  - Port Range Limitation (nmap -p 1-1000 localhost): Constrained the enumeration footprint efficiently across the primary well-known ports (1-1000) to optimize scan times and focus on high-value targets.
  - Aggressive Auditing (nmap -A localhost): Combined traceroute, OS detection, service version tracking, and NSE (Nmap Scripting Engine) default scripts to produce a comprehensive attack-surface footprint.

- WHAT I LEARNED:
  I learned that a simple port scan only maps out the doors of a burning building, whereas version detection 
  (-sV) and aggressive scanning (-A) tell you exactly what kind of lock is on the door. It forces target 
  services to respond to specific queries, revealing minor system variations that completely give away their 
  software versions.

- WHAT IT MEANS IN REAL LIFE:
  In a target reconnaissance phase, a threat actor will never rely on standard port list assumptions (e.g., assuming 
  Port 80 is always basic Apache). They use service version detection to cross-reference exact version strings 
  against public CVE vulnerability databases. If an administrator leaves an unpatched or legacy service running, 
  an attacker using Nmap can pinpoint the exact exploit script required to achieve Remote Code Execution (RCE).

    A SID is a unique, variable-length string used by Windows to identify a user account, group, or computer.
    Windows uses the SID internally in Access Control Lists (ACLs) to manage permissions rather than relying on usernames.
    
  Anatomy of a typical SID:
  S-1-5-21-1171287513-3642516788-2358256967-1004

    S — Identifies the string as a SID.
    1 — Revision level (always 1).
    5 — Identifier Authority (NT Authority).
    21-1171287513-3642516788-2358256967 — Domain or Local Machine Identifier (shared by all accounts belonging to this computer or Active Directory domain).
    1004 — The RID (Relative Identifier).

- HASH CONCEPTS & DICTIONARY ATTACKS:
  * Hashes are one-way cryptographic digests. Passwords are stored as hashes to prevent direct leaks.
  * Dictionary attacks compute hashes of known words (e.g., rockyou.txt) to find matches instantly.
  * Strong password policies require length (14+ chars) and high entropy to widen search space beyond dictionary bounds.

- DEFENSIVE USE:
  * Forensics: Extracting SAM/NTDS.dit hashes to determine exposure scope.
  * Defense: Auditing Active Directory databases for weak, crackable passwords using Hashcat.
