Date: October 20, 2026

1. 3 DNS Lookups and What Each Tells You:
   - Standard A/AAAA Record Query (e.g., SaaS, updates): Establishes baseline operational traffic and legitimate enterprise tool usage.
   - High-Entropy Subdomain Query (randomized strings): Indicates potential Domain Generation Algorithm (DGA) activity or DNS tunneling used to bypass firewalls and exfiltrate data.
   - Repeated NXDOMAIN (Non-Existent Domain) Floods: Highlights malware checking for internet connectivity or scanning for active Command and Control (C2) servers.

2. Server Followed (TCP Stream Analysis):
   - Used Wireshark's "Follow TCP Stream" feature on an external IP conversation to reconstruct the raw application-layer session (HTTP/plaintext protocols), revealing exact data payloads, requested paths, or unencrypted authentication.

3. What a Port Scan Looks Like in Wireshark:
   - Appears as a rapid, sequential/randomized wave of TCP SYN packets originating from a single source IP across dozens or hundreds of ports. Closed ports reply with `RST, ACK`; open ports reply with `SYN, ACK`.

4. When to Use `tcpdump`:
   - Use on headless/remote servers via SSH where a GUI is unavailable.
   - Use in low-resource environments or for rapid live captures (`-w capture.pcap`) and quick inline terminal inspection before pulling `.pcap` files down for deep analysis in Wireshark.

DAY 18 - Hydra + fail2ban (Attack and Defence)
Date:November 02, 2026
========================================================================

1. WHY WEAK PASSWORDS FALL FAST (HYDRA CONCEPTS)
- Hydra is a parallelized login cracker supporting dozens of network protocols (SSH, FTP, HTTP, SMB, etc.).
- Because it opens multiple simultaneous connections (-t) and tests common leaked passwords from wordlists
   (like rockyou.txt) at machine speed, predictable passwords fall in seconds.

2. ATTACK SIDE (HYDRA & AUTH.LOG)
- Hydra success output:
  [22][ssh] host: 127(dot)0(dot)0(dot)1   login: testuser   password: sunshine123

- Log evidence in /var/log/auth.log:
  sshd-session[...]: Failed password for testuser from 127.0.0.1 port ... ssh2
  (Followed by: PAM 4 more authentication failures; logname= uid=0 euid=0 tty=ssh ruser= rhost=127.0.0.1 user=testuser)

3. DEFENCE SIDE (FAIL2BAN BAN CONFIRMATION)
- After enabling the [sshd] jail (maxretry = 3, bantime = 600) and running Hydra with wrong passwords, fail2ban detected the repeated failures and blocked the attacking IP:
  Status for the jail: sshd
  |- Filter
  |  |- Currently failed: 3
  |  |- Total failed:     3
  `- Actions
     |- Currently banned: 1
     |- Total banned:     1
     `- Banned IP list:   127(dot)0(dot)0(dot)1

4. THREE DEFENCES AGAINST SSH BRUTE FORCE
   - Fail2ban (or rate-limiting): Automatically parses authentication logs and dynamically adds firewall drop rules to ban offending IPs after a threshold of failed attempts.
   - SSH Key-Based Authentication Only: Disabling PasswordAuthentication in /etc/ssh/sshd_config removes password-guessing attack vectors completely.
   - Firewall Allow-Listing / Non-Standard Port: Restricting port 22 via UFW/iptables to trusted admin IPs (and/or moving SSH off port 22) blocks automated internet-wide scanners from reaching sshd.

5. SELF-CHECK
   - Network IP vs 127.0.0.1: fail2ban ignores 127(dot)0(dot)0(dot)1/8 by default so local processes do not lock out the host machine.
   - SSH keys vs fail2ban: fail2ban reacts only after failed attempts occur (and struggles against distributed botnets), whereas SSH keys prevent password brute-forcing entirely.

1. The grep pipeline that lists the top 10 attacking IPs in auth.log, and what each part does.
   grep "Failed Password" /var/log/auth.log | grep -oE '[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}' | sort | unique -c | sort -rn | head -n 10

2. What do sort -rn and uniq -c do?
   (a) sort -rn: Sorts lines numerically (-n) from highest to lowest (-r reverse), ensuring 100 ranks above 20 rather than sorting alphabetically.
   (b) uniq -c: Removes adjacent duplicate lines and prepends the number of times each line occurred (which is why sort must always run before uniq).

3. Windows Event IDs 4624, 4625, 4688, 4720, 7045, 1102: what each means.
   4624: Successful account logon (tracks logon type, user, and source IP).
   4625: Failed account logon (indicates brute-force attempts, password spraying, or mistyped credentials).
   4688: A new process was created (shows what executable ran and its parent process/command-line arguments).
   4720: A new local or domain user account was created (often used by attackers to establish persistence).
   7045: A new Windows service was installed in the System log (commonly used for privilege escalation or persistence).
   1102: The Security audit log was cleared (a strong indicator of an attacker covering their tracks).

4. Nmap -sV and closed vs filtered
   -sV (Service/Version Detection): Probes open ports to determine the exact service name and software version running behind the port.
   closed vs filtered: A closed port is reachable and responds with a TCP RST (Reset) packet, proving no firewall is blocking it, but no
   application is listening on it. A filtered port sends no response (or an ICMP unreachable error) because a firewall or packet filter
   is dropping Nmap's probes, preventing Nmap from knowing whether the port is open or closed.


5. Wireshark Filters
   Port scan filter: tcp.flags.syn == 1 and tcp.flags.ack == 0 (identifies SYN scan probes) or tcp.flags.reset == 1 (identifies RST responses from closed ports).
   DNS filter: dns (or udp.port == 53).

6. Autopsy: 5 Artefacts and What Each Proves
   Prefetch files (C:\Windows\Prefetch\*.pf): Proves a specific executable was run on the system, how many times it ran, and its last execution timestamps.
   Windows Registry (Run / RunOnce keys or UserAssist): Proves persistence mechanisms configured to launch at startup (Run keys) or GUI programs launched by a specific user (UserAssist).
   Browser History / Downloads (History SQLite DB): Proves which URLs a user visited, search queries made, and malicious files downloaded with timestamps.
   LNK (Shortcut) Files & Jump Lists: Proves a user opened specific local, network, or external USB files—even if the original file was later deleted.
   USBSTOR Registry Key (SYSTEM\CurrentControlSet\Enum\USBSTOR): Proves specific external USB storage devices (vendor, product, serial number) were connected to the machine.

- Investigation Method & Artefacts (without sharing raw lab answers):
  (1) Date and Start Time of NetSupport RAT Traffic:
     - Filter: frame contains "NetSupport"
     - Method: Set View -> Time Display Format -> UTC Date and Time of Day, sorted ascending by packet number, and read the timestamp on the first matching HTTP C2 packet.
     - Why it worked: NetSupport Manager transmits cleartext HTTP User-Agent/header strings containing "NetSupport" on initial check-in.

  (2) IP Address and MAC Address of the Infected Windows Client:
     - Filter: frame contains "NetSupport"
     - Method: Inspected the first matching packet's IPv4 layer (Source Address) and Ethernet II frame header (Source MAC).
     - Why it worked: Outbound C2 HTTP requests originate directly from the compromised client's network interface.

  (3) Host Name of the Infected Windows Client:
     - Filters: dhcp or nbns
     - Method: Checked DHCP Request Option 12 (Host Name) and NetBIOS Name Service (NBNS) registration packets matching the infected client's MAC/IP address.
     - Why it worked: Windows workstations broadcast their configured computer name in cleartext during DHCP lease requests and local NBNS registration packets.

  (4) User Account Name from the Infected Windows Client:
     - Filter: kerberos.cname_string == 1 and !(kerberos.CNameString contains "$")
     - Method: Added kerberos.CNameString as a custom column in Wireshark and verified the source IP matched the infected Windows client.
     - Why it worked: Active Directory clients send the logged-in user's principal name in cleartext during Kerberos AS-REQ/TGS-REQ exchanges; excluding "$" filtered out machine accounts (HOSTNAME$) to isolate the user account.
