=== LEVEL 1 ===
TASK: Read a file in the home directory

WHAT I DID:
Used cat to read a file called readme

WHAT I FOUND:
cat readme returned the password for the next level.
The cat command prints file contents directly to the terminal.

WHAT IT MEANS IN REAL LIFE:
During incident response, the first thing I do on any
compromised server is read log files and config files.
cat is the fastest way to read any file on a Linux system.

---

=== LEVEL 2 ===
TASK: Read a file with a special character "-" in the name

WHAT I DID:
Used cat ./-  instead of cat -

WHAT I FOUND:
cat - is interpreted as "read from keyboard input" not a file.
Adding ./ tells the system it is a file path, not a flag.

WHAT IT MEANS IN REAL LIFE:
Attackers sometimes name malicious files with special
characters to confuse administrators and hide them.
Knowing how to read files with unusual names is essential
for finding attacker-planted files during investigations.

---

=== LEVEL 3 ===
TASK: Read a file with spaces in its name

WHAT I DID:
Used cat "spaces in this filename" with quotes around the name

WHAT I FOUND:
Without quotes, Linux treats each space as a separator
between different arguments — so it looks for 4 separate
files. Quotes tell Linux to treat the whole thing as one name.

WHAT IT MEANS IN REAL LIFE:
Log files and attacker-dropped files often have unusual
names. Being comfortable reading any filename regardless
of special characters is a basic IR skill.

---

=== LEVEL 4 ===
TASK: Find and read a hidden file inside a directory

WHAT I DID:
Navigated to the inhere folder and ran ls -la to reveal
hidden files, then read the hidden file with cat

WHAT I FOUND:
Hidden files on Linux start with a dot (.)
Regular ls does not show them — you need ls -la
The -a flag shows all files including hidden ones
The -l flag shows full details (permissions, owner, size)

WHAT IT MEANS IN REAL LIFE:
Attackers hide malware and persistence files as dotfiles.
During forensic investigation, always run ls -la — never
just ls. Hidden files are one of the first places to check
for attacker activity on a compromised Linux system.

---

=== LEVEL 5 ===
TASK: Find a file with specific properties across many directories

WHAT I DID:
find inhere/ -type f -size 1033c ! -executable | xargs cat

WHAT I FOUND:
The file was buried deep inside subdirectories.
find with filters located it instantly without manual searching.
Properties used: file type, exact size in bytes, not executable.

WHAT IT MEANS IN REAL LIFE:
During incident response I might know properties of a
file an attacker dropped (size, type, permissions) but
not its location. find lets me hunt it across an entire
server in seconds. This same technique is used to find
web shells, backdoors, and malicious scripts.

---

=== LEVEL 6 ===
TASK: Find a file owned by a specific user and group anywhere on the server

WHAT I DID:
find / -user bandit7 -group bandit6 -size 33c 2>/dev/null | xargs cat

WHAT I FOUND:
Searching from root (/) covers the entire system.
2>/dev/null hides hundreds of "Permission denied" errors
so only the successful result shows.
File ownership (user and group) is a key Linux file property.

WHAT IT MEANS IN REAL LIFE:
After a breach, I can hunt for files owned by a specific
compromised account across the whole server. If an attacker
created files as a particular user, this command finds them
all instantly. The 2>/dev/null trick is standard practice
to suppress noise during large searches.

=== LEVEL 7 ===
TASK: Find a specific string in a large file

WHAT I DID:
grep "millionth" data.txt

WHAT I FOUND:
The file data.txt contained thousands of lines.
grep searched every line and returned only the matching one
containing the word "millionth" instantly.

WHAT IT MEANS IN REAL LIFE:
Server log files can contain millions of lines.
grep is how security engineers find specific events —
a username, an IP address, an error code, a malware string —
without reading the entire file. This is the single most
used command in log analysis and is used in every
real-world investigation.

---

=== LEVEL 8 ===
TASK: Find the one unique line that appears only once

WHAT I DID:
sort data.txt | uniq -u

WHAT I FOUND:
sort rearranged all lines alphabetically, grouping duplicates.
uniq -u then filtered to show only lines appearing exactly once.
Every other line appeared multiple times — one line was unique.

WHAT IT MEANS IN REAL LIFE:
In security, the anomaly is the threat. A login that
happened once at 3AM from an unusual IP stands out against
hundreds of normal logins. This technique finds the needle
in the haystack — the one event that doesn't fit the pattern.
Used in threat hunting and log analysis daily.

---

=== LEVEL 9 ===
TASK: Extract readable text from a binary file

WHAT I DID:
strings data.txt | grep '=='

WHAT I FOUND:
data.txt was a binary file — mostly unreadable garbage.
strings extracted all human-readable sequences from it.
grep '==' filtered for lines marked with == signs.
The password was hidden among the readable strings.

WHAT IT MEANS IN REAL LIFE:
Malware is a binary file. strings is the first tool
a malware analyst runs — it extracts hardcoded URLs,
IP addresses, file paths, registry keys, and error messages
from malware without executing it. This is core static
malware analysis and is used in every DFIR investigation.

---

=== LEVEL 10 ===
TASK: Decode base64 encoded data

WHAT I DID:
base64 -d data.txt

WHAT I FOUND:
The file contained a long base64 string — looks like
random letters and numbers ending in ==
Decoding revealed a plain English sentence with the password.

WHAT IT MEANS IN REAL LIFE:
Attackers encode malicious payloads in base64 to bypass
security filters and avoid detection. PowerShell malware
almost always uses base64. Encoded strings in logs,
emails, and files are an immediate red flag. Decoding
them is a daily task in SOC and IR work.

=== LEVEL 11 ===
TASK: Decode ROT13 encoded text

WHAT I DID:
cat data.txt | tr 'A-Za-z' 'N-ZA-Mn-za-m'

WHAT I FOUND:
The file contained: "Gur cnffjbeq vf [encoded text]"
After decoding with tr (translate): "The password is [password]"
ROT13 shifts every letter exactly 13 positions in the alphabet.

WHAT IT MEANS IN REAL LIFE:
ROT13 is a simple substitution cipher used for basic
obfuscation. While not strong encryption, it appears
in CTF challenges and occasionally in real malware to
hide strings from basic scanning. The tr command is
the Linux tool for character-level text transformation —
used in log parsing and data cleaning.

=== LEVEL 12 ===
TASK: Decompress a file compressed multiple times in different formats

WHAT I DID:
Used file command to identify compression type at each stage.
Renamed files with correct extensions.
Used gunzip for .gz, bunzip2 for .bz2, tar -xf for .tar
Repeated until reaching plain ASCII text.

WHAT I FOUND:
The file was wrapped in 7+ layers of different compression.
Each layer required identifying the format first with file
then using the correct decompression tool.
file command correctly identifies file type regardless
of the filename extension.

WHAT IT MEANS IN REAL LIFE:
Attackers layer compression to slow down analysis and
evade detection tools. Malware samples are often delivered
in nested compressed archives. The ability to unwrap any
compression format is essential for malware triage.
The file command is more reliable than file extensions
which can be faked.

=== LEVEL 13 ===
TASK: Authenticate to a server using SSH private key instead of password

WHAT I DID:
Found sshkey.private in the home directory.
Transferred it to local machine using scp.
Fixed permissions with chmod 400.
Used ssh -i to authenticate with the key.

WHAT I FOUND:
SSH refuses to use a private key if permissions are too
open — it must be readable by owner only (chmod 400).
Key-based auth does not require a password at all.
The key file must be protected like a password itself.

WHAT IT MEANS IN REAL LIFE:
Every AWS EC2 instance, GitHub account, and production
server uses SSH key authentication. Passwords are weak —
keys are the standard. As a security engineer I will
configure, manage, and audit SSH keys constantly.
A leaked private key is equivalent to a leaked password
and must be rotated immediately.

=== LEVEL 14 ===
TASK: Connect to a local port using netcat

WHAT I DID:
nc localhost 30000
Pasted the level 14 password when prompted.
Received the next password in response.

WHAT I FOUND:
nc (netcat) opens a raw TCP connection to any host and port.
It sends and receives data directly with no encryption.
The service on port 30000 accepted the password and
returned the next one.

WHAT IT MEANS IN REAL LIFE:
Netcat is called the Swiss Army knife of networking.
Security engineers use it to: test if ports are open,
send raw data to services, debug network issues, and
simulate basic client-server communication.
Attackers also use it to create backdoors and transfer
files — knowing how it works is essential for both
offense and defense.

---

=== LEVEL 15 ===
TASK: Connect to a port using SSL/TLS encryption

WHAT I DID:
openssl s_client -connect localhost:30001 -ign_eof
Pasted the password when connected.

WHAT I FOUND:
Unlike nc, openssl s_client wraps the connection in
SSL/TLS encryption — the same as HTTPS.
-ign_eof keeps the connection open after pasting the password.
Without -ign_eof the connection closes before the
server can respond.

WHAT IT MEANS IN REAL LIFE:
HTTPS, SMTPS, and any secure service use SSL/TLS.
openssl s_client lets me inspect encrypted connections
by hand — check certificates, test SSL configs, and
verify encryption is working. Used in security audits
and penetration testing to verify that services are
correctly configured.

=== LEVEL 16 ===
TASK: Find which port in a range is running SSL then connect to it

WHAT I DID:
Scanned ports 31000–32000 to find which ones were open.
Connected to the correct port using openssl s_client.
Received an SSH private key instead of a password.

WHAT I FOUND:
Not all open ports run the same service.
Scanning identifies what is running where.
Some ports returned the input back (echo service) —
the correct one returned a private key.

WHAT IT MEANS IN REAL LIFE:
Port scanning is fundamental recon in both penetration
testing and incident response. During IR, scanning a
compromised server reveals backdoors listening on
unusual ports. Attackers frequently run C2 (command
and control) servers on non-standard ports to avoid
detection.

SECTION 2: AUTH.LOG ANALYSIS
================================================

=== TASK: Analyse SSH authentication failures ===

COMMANDS USED:
grep 'authentication failure' auth.log | grep -oE 'rhost=[^ ]+' | cut -d= -f2 | sort | uniq -c | sort -rn | head -10

WHAT I FOUND:
- Multiple IPs attempted repeated SSH logins
- Attacks were automated (too many attempts too fast for a human)
- The rhost= field identified attacker IP addresses
- sort + uniq -c counted attempts per IP
- sort -rn ranked highest to lowest

WHAT IT MEANS IN REAL LIFE:
This is a live SSH brute-force attack pattern.
An automated tool (like Hydra or Medusa) is cycling
through username/password combinations.

If I found this on a real server I would:
1. Block all attacking IPs at the firewall immediately
2. Check if any of them succeeded:
   grep "Accepted password" auth.log
3. Alert the SOC team with IP list and timestamps
4. Recommend enabling fail2ban to auto-block after
   X failed attempts
5. Recommend disabling password auth entirely —
   enforce SSH keys only

================================================
OVERALL WEEK 1 TAKEAWAYS
================================================

1. Linux CLI is not optional — it is the primary tool
   of every security engineer, analyst, and forensic
   investigator. Every command learned this week
   appears in real investigations.

2. find, grep, strings, and sort/uniq are the four
   most important commands for forensic file analysis.

3. SSH key authentication is the security standard —
   passwords are weak. Every cloud server uses keys.

4. Attackers use encoding (base64, ROT13), compression,
   and hidden files to evade detection. These exact
   techniques appear in real malware.

5. The anomaly is always the threat — sort | uniq -u
   thinking applies to every log analysis task.
   What happened once that normally happens zero times?
